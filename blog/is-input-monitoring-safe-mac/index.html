Is Input Monitoring safe on a Mac?

Keyboard sound apps need Input Monitoring to hear your key presses. Here's what that permission allows, how it differs from a keylogger, and how to check any app yourself.

Download for MacTry it in your browser →

Updated November 2, 2026

Short answer: Input Monitoring is as safe as the app you give it to. It lets an app see each key you press in other apps, which is exactly what a keylogger needs too. So the real question is what the app does with those keys: whether it stores them, sends them somewhere, or does neither. macOS keeps password fields out of reach, and you can switch the permission off per app at any time in System Settings › Privacy & Security › Input Monitoring.

What Input Monitoring lets an app see

Apple's wording is short: “Some apps can monitor your keyboard, mouse, or trackpad even when you're using other apps.” You choose which ones (Apple: control access to input monitoring). That covers key presses and pointer input. It doesn't cover your screen, your files, your microphone or the network. Screen, files and microphone each have their own switch; internet access has none at all.

Is a keyboard sound app a keylogger?

It uses the same door, so the worry is fair. What makes something a keylogger is what happens next: it writes your keys down or sends them somewhere. A keyboard sound app only needs to know that a key went down, and which one, so it can pick a sound. It has no reason to keep anything.

You can't read an app's code, but you can check the two things that matter. First, does its privacy policy say plainly that it never stores or sends what you type? Second, does it make network connections? An app that never connects out can't send your keys anywhere, and one that stores nothing leaves nothing behind. The network test below takes a few minutes.

Is a keyboard sound app safe for Mac?

Most are small, single-purpose apps. Before you grant Input Monitoring, run through this list:

  • Who makes it? A developer you can name and contact is a better bet than an anonymous download.
  • Is it notarized, or from the Mac App Store? macOS checks apps from outside the App Store for Apple's notarization, and warns you or blocks the app when it's missing.
  • Which permissions does it ask for? Input Monitoring is enough for sounds. Be wary of an app that also wants Accessibility, Full Disk Access or the microphone without saying why.
  • What does its privacy policy say about keystrokes? Look for a direct sentence, not a vague one.
  • Does it have analytics, and does it connect out? Read the policy, then check with a firewall.

Secure input: why password fields are protected

When you click into a password field, macOS turns on secure input. While it's on, apps that monitor input don't receive your keystrokes, Input Monitoring or not. Terminal lets you switch on the same protection for everything you type there, with Terminal › Secure Keyboard Entry. Apple says it “can prevent other apps on your computer or the network” from detecting what you type (Apple: Secure Keyboard Entry).

That's also why keyboard sounds go quiet in password fields. And if an app leaves secure input switched on after you've moved on, keyboard sound apps hear nothing anywhere until it lets go.

How to enable or revoke Input Monitoring

  1. Open the list. Choose Apple menu › System Settings › Privacy & Security, then click Input Monitoring.
  2. Read every name. Each app in the list either asked for this permission or was added by hand. Look up any you don't recognize.
  3. Switch off what you don't use. Turn an app's switch off and it loses access to keys you press in other apps. macOS may ask for your password or Touch ID.
  4. Remove apps you've deleted. Select the app and click the Remove button (−) under the list.
  5. Turn one back on later. Flip its switch on again. Some apps need a restart to notice; Keyslam shows a Relaunch Keyslam button when it does.

A keyboard sound app usually asks for the permission the first time it opens. Keyslam's menu has an Open Settings button that jumps straight to this list, and its install steps and requirements show where that fits in setup.

How to check whether an app sends anything

  1. Install a firewall that asks. LuLu is free and open source (macOS 10.15 or later). Little Snitch is a paid option. Both alert you when an app tries to connect out.
  2. Open the app you're testing. Leave it running and type normally for a few minutes, in a few different apps.
  3. Watch for alerts with its name. Any connection attempt shows up with the app's name and the server it wants to reach. You decide whether to allow it.
  4. Check Activity Monitor for a second opinion. Open Activity Monitor and click Network. It shows how much data your Mac is sending, and you can sort the list by process.

With Keyslam you should see nothing: it makes no network connections. Buying opens Stripe Checkout in your browser, so any connection you see then belongs to the browser, not to Keyslam. The license key you paste is checked on your Mac.

Questions about Input Monitoring

Does Input Monitoring let an app see my passwords?

Not from password fields. macOS switches on secure input there and doesn't deliver those keystrokes to apps that monitor input. A password typed into an ordinary text box is different: any app with Input Monitoring can see it like any other text.

What happens if I turn Input Monitoring off for a keyboard sound app?

It can no longer hear keys in other apps, so it goes quiet. Nothing else breaks. When Keyslam opens without the permission, its menu says “Needs Input Monitoring access” and offers an Open Settings button.

Is Accessibility permission the same thing?

No. Input Monitoring lets an app watch your keyboard, mouse and trackpad. Accessibility lets an app control your Mac through accessibility features, which is broader. A keyboard sound app needs only Input Monitoring, and Keyslam asks for nothing else.
